05 / Method

How I work

The same four steps whether it is a billing screen, a SQL study, or a pitch deck.

(01)

Watch the real process

Before any code: how does the work actually happen today, including the small corrections people make without noticing they make them?

(02)

Get the structure right first

Schema before screens, cleaning decisions before charts. A structure you patch later is a structure that quietly lies to you.

(03)

Build the unhappy path

Timeouts, dropped requests, missing rows, a queue at the counter. This is what separates finished from demoed.

(04)

Lead with the decision

State the recommendation, keep the method underneath for whoever wants it. An analysis nobody acts on has not finished.
